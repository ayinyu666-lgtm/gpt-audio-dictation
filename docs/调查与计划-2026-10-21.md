## 一、落盘目录：找到两个真问题

### 1.1 根目录被改回上一级（真凶）

- 当前 `writer/config.json:3`：`rootDir = C:\Users\YuLong\Desktop\硕士学习文件`
- 备份 `writer/config.json.bak:3`：`rootDir = C:\Users\YuLong\Desktop\硕士学习文件\冬季学期`
- 证据：今天 14:33 之前的文件写在 `冬季学期\` 下，14:34 之后新建了根级的 `硕士学习文件\回收-舒伯特\`。

**后果**：同一门课「回收-舒伯特」今天的转录被劈成两棵树
- `硕士学习文件\冬季学期\回收-舒伯特\原始录音\`（13:31 / 13:56 / 14:31，止于 14:33）
- `硕士学习文件\回收-舒伯特\原始录音\`（14:55 / 15:15，以及后续）

### 1.2 课程名与目录名不一致（用户看不到文件的原因）

`resolveTarget()`（`writer/writer.mjs:291-307`）拼法：
```
rootDir \ safeName(course) \ subDir \ {date} {weekday} {time}.md
```
`safeName`（`writer.mjs:262-272`）只做非法字符过滤，**没有别名/模糊匹配/存在性检查**。

课程清单（config.json courses）与桌面实际目录对照：

| 课程清单里的名字 | 桌面有无同名目录 | 说明 |
| --- | --- | --- |
| 回收-舒伯特 | 有（`冬季学期\回收-舒伯特`） | 但课程的资料目录其实叫 **回收技术-舒伯特** |
| AVEVA-舒伯特 | 有 | 正常 |
| 系统技术-马丁 | **无** | 会新建空目录 |
| 系统技术-大作业 | **无**（近似：`系统大作业`） | |
| 回收-希望 | **无**（近似：`回收技术-希望`） | |
| 绿色-Nitsche | 有 | 正常 |
| 系统控制-Liebscher | 有 | 正常 |

**用户「回收技术-舒伯特 下没看到落盘文件」的答案**：内容写进了 `回收-舒伯特`，两个名字指的大概率是同一门课（舒伯特教的回收技术）。

### 1.3 回答用户的问题：会不会自动建文件夹

**会。** `writer.mjs:298` `mkdirSync(dir, { recursive: true })` 会连课程目录和 `原始录音` 一起建。
但 `subDir`（值 = `原始录音`）**只在 config.json 里手工改，扩展里没有任何入口**（`extension/` 下 grep 零命中）——所以面板上根本没有"选子文件夹"这回事。

### 1.4「一段录音一次落盘」的误解

不是。一次录音 = 文件中一个 `## HH:MM:SS　第 N 段` 条目；**一个文件 = 一个 ChatGPT 会话**。
所以 AVEVA 今天 3 个文件不是异常，是上下文超限切换了 3 次会话。

## 三、新会话切换（调查结论）

- 会话标识 = `queueRouteKey()`（`page-hook.js:97-105`），就是 `https://chatgpt.com/c/<id>`。
- **已有** URL 轮询：`page-hook.js:1423-1446`，600ms 一次比对 `lastHref`。所以切换**能被发现**。
- 但被发现后只做状态重置，三个缺陷：
  1. `S.sessionStart` 不重置（只在 `api.start` `:724` 设）→ 新会话的内容被写进旧文件
  2. `:1439` 直接丢弃 `S.pending` → 正在录的那段丢失，且不记 `recordSegment`
  3. **队列迁移只支持 `/` → `/c/...`**（`rootToConversationRoute` `:106-114`），会话→会话的 job 永远不被迁移、不超时、不报错，冻在 localStorage 里
- **没有任何上下文上限检测**。`readUi()`（`:567-580`）只认按钮 aria-label。
- 多标签页无锁：`autoStart` 默认开（`panel.js:33`），每个 ChatGPT 标签页 5 秒后自动启动（`:1452-1457`）→ 用户在旧标签页的扩展实例可能还在跑。

三条路线：
- **A 跟随 URL**：改 `:1437-1443`，重置 sessionStart/段号，别丢 pending。低风险，但会话→会话的队列迁移不安全（旧轮次已不在 DOM，指纹匹配不上）。
- **B 自动开新会话**：`tryStart`/`finalizingTick` 检测不到「听写」按钮（上限特征）→ 跳 `https://chatgpt.com/`。队列迁移这条路正好被现有逻辑覆盖。中等成本，风险：可能误触发。
- **C 提示用户 + 检测到即跟随**：成本最低，只加提示。

**建议：C 打底 + B 做成开关（默认关），A 的队列迁移限定在同一会话的 URL 变体。**

## 四、提示词注入（调查结论）

- 输入框是 contenteditable：`COMPOSER_SELECTOR = 'div.ProseMirror[contenteditable="true"]'`（`page-hook.js:1075`）
- **现有代码只读不写**：grep `execCommand|insertText|InputEvent|dispatchEvent|textContent =` 在 page-hook.js 零命中。需新写。
- 面板**已有** textarea 先例：`promptBox`（`panel.js:648-651`，7 行只读，由 `translationPrompt()` 填充、`btnCopyPrompt` 复制）。改成可编辑 = 去掉 `readOnly` + 加 `onchange` 存进 `settings` + `DEFAULTS` 加默认值。
- 持久化：面板用 `chrome.storage.local` key `gad`（`panel.js:53,70`）；页面侧只有 localStorage。
- 消息通道：ui→main `send()`（`panel.js:102-104`），main 侧 switch 在 `page-hook.js:279-406`，加一个 `injectPrompt` 类型即可。
- **污染风险（关键）**：注入的消息本身不会单独落盘（`queueSave` 只在 `recordSegment` 里调用，`:1047-1050`）。但 `resolveJobTurn` 的兜底 `if (fresh) return turns[turns.length - 1];`（`:1252`）可能在指纹都没命中时把"提示词+它的回复"当成某段转录存进去。**必须给注入的消息打标记并在匹配时排除。**
- 注入时机：`state==='idle'` 且无 pending/recording/transcribing；每个会话只注入一次（用 `promptInjectedRoute` 记住）；保留手动「重新注入」按钮。

## 五、面板目录选择 UI（调查结论）

`secSave`（`panel.js:678-699`）现有 15 个控件，**课程选择不在其中**——它在 `secPolicy`（`panel.js:665`）。这就是"顺序不对"的结构原因。

- `saveTarget`（`panel.js:1020-1022`）显示 `writerRoot + '\' + active`，**漏了 subDir** → 面板告诉用户的路径和实际写入路径不一致。
- `/root-candidates`（`writer.mjs:164-203`）扫的是 **桌面/文档的一级子目录**（找含 .md/.txt 的），返回前 12 个。设计意图是**重装后找回旧归档**，跟"根目录下的子文件夹"毫无关系 → 用户觉得没意义是对的。它需要 3 次点击（发现 → 选 → 使用）且通常无效。
- `/set-course` 是**死路由**（`writer.mjs:473-484`，`extension/` 下零调用），writer 的 `course` 一直是 `""`。

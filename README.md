# GPT Audio Dictation

**面向 ChatGPT 网页端的音频转录、自动分段与本地归档扩展。**

[![checks](https://github.com/ayinyu666-lgtm/gpt-audio-dictation/actions/workflows/ci.yml/badge.svg)](https://github.com/ayinyu666-lgtm/gpt-audio-dictation/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

<img src="extension/icons/icon128.png" width="88" alt="GPT Audio Dictation icon">

它驱动 ChatGPT 网页自身的听写功能，把长音频自动拆成多个片段，继续下一段，并在本地归档模块开启时保存“本段原始转录 + 紧随其后的 GPT 回答”。它并不只用于课堂或翻译：讲座、访谈、会议记录、口述笔记、语言学习和其他需要连续转录的场景都可以使用。

> 本项目不是 OpenAI 官方产品，与 OpenAI 没有隶属或背书关系。ChatGPT 网页结构和按钮文案发生变化时，可能需要更新页面适配层。

## 能做什么

- 跟踪 ChatGPT 正在使用的麦克风流，不另开录音设备。
- 根据说话与停顿自动结束当前段，并继续录下一段。
- 适配浏览器把后台标签页定时器降频的情况。
- 中文、Deutsch、English 三套首次使用引导。
- 每次保存只读取对应的用户转录和紧随其后的 GPT 回答，不把积压段落全部写成最后一条回答。
- 分类在段落开始时冻结；中途切换分类不会把旧段写进新目录。
- 保存任务按 `saveId` 独立持久化，支持刷新、关闭标签页、扩展重载和服务暂时离线。
- 长会话中的旧轮次即使被 ChatGPT 从页面 DOM 移走，也会使用精确/宽松文本指纹继续认领；一个匹配不到的任务不会堵住其他可保存段落。
- 上下文满了自动跳到新会话，先抢救正在录的那一段，再接着录下一段。
- 进入新会话后自动发一句提示词，让 ChatGPT 回忆它记忆里的任务要求；提示词内容可改，也可关掉。
- 临时错误自动退避重试；不可自动解决的任务保留为失败状态，可在面板处理。
- Windows 原生目录选择、可写探针、配置备份与恢复。
- 本地 Markdown 写入使用内容摘要、重复检测、半段恢复和冲突保护。

## 它不负责什么

- 不提供语音识别模型，转录由已登录的 ChatGPT 网页完成。
- 不需要 OpenAI API Key，也不会把内容发送到本项目自己的服务器。
- 不保证绕过 ChatGPT 的账号、地区、额度或功能限制。
- 不自动修改 ChatGPT 的账号记忆。新会话提示词只是提醒 ChatGPT 去回忆它自己的记忆，不会写入或修改记忆内容。

## 典型用途

| 场景 | 做法 |
|---|---|
| 讲座 / 课程 | 自动分段转录，按主题归档到 Markdown |
| 访谈 / 会议 | 保存原始转录和后续整理结果，便于复查 |
| 个人口述笔记 | 连续说，自动续录并归档到指定目录 |
| 语言学习 | 要求 ChatGPT 翻译、解释或整理为目标语言 |
| 调研记录 | 在面板自定义提示词，让回答以摘要、术语表或其他格式呈现 |

## 系统要求

- Windows 11 优先；其他 Windows 版本可按相同方式尝试。
- Microsoft Edge 或其他 Chromium 浏览器。
- Node.js 22 或更高版本，仅在启用本地归档时需要。
- 一个可正常使用网页听写功能的 ChatGPT 账号。

## 快速安装

### 1. 下载并解压

从 GitHub Releases 下载 Windows 包，解压到普通本地文件夹。不要直接在压缩包预览窗口中运行。

### 2. 加载扩展

1. 双击 `install.bat`。
2. Edge 会打开扩展管理页。
3. 开启“开发人员模式”。
4. 选择“加载解压缩的扩展”。
5. 选择项目中的 `extension` 文件夹。
6. 打开或刷新 ChatGPT 页面。

Chromium 要求用户手动加载未上架商店的扩展，这是浏览器安全限制。

### 3. 启动本地归档服务

双击：

```text
writer\start-writer.bat
```

服务只监听：

```text
http://127.0.0.1:8799
```

### 4. 首次使用

1. 在浮动面板中打开“归档 GPT 回答”。
2. 按面板从上到下的顺序设置落盘位置：① 落盘根目录 → ② 子文件夹 → ③ 当前课程。
3. 先用“快速测试”完成一段短测试。
4. 确认转录、继续录音和本地文件都正常后，切换“正式模式”。
5. 点“开始”才会录音。扩展默认**不**自动开始转录，页面打开后需要你手动点一次。

## 本地归档格式

默认目录结构：

```text
选择的根目录\
  分类名\
    2026-10-17 周六 17-05.md
```

默认文件内容：

```md
# 分类名

- 日期：2026-10-17（周六）
- 开始时间：17:05:12
- 会话：https://chatgpt.com/c/...
- 来源：GPT Audio Dictation（ChatGPT 网页音频转录与本地归档）

## 17:05:18　第 1 段

**原始转录**

...语音转录...

**GPT 回答 / 处理结果**

...ChatGPT 输出...
```

文件名模板和是否写入原始转录、GPT 回答可在 `writer/config.json` 中调整。公开示例见 [`writer/config.example.json`](writer/config.example.json)。

如果希望分类目录下再放一层子目录，在面板的“② 子文件夹”里填名字（如 `原始录音`）：

```text
选择的根目录\
  课程名\
    原始录音\
      2026-10-17 周六 17-05.md
```

**留空时文件直接写入课程目录**，不再多一层。`writer/config.json` 里的 `subDir` 是默认值，面板里改会覆盖它。

## 课程目录别名

课程名和磁盘上的目录名不一致时，在 `writer/config.json` 里加一条映射：

```json
"courseDirs": {
  "课程简称": "磁盘上的目录名"
}
```

这样面板里仍显示“课程简称”，文件却写进“磁盘上的目录名”。适合合并同一门课的两个叫法，文件不会被劈成两棵树。

## 新会话与上下文上限

ChatGPT 免费版长对话容易触发上下文上限。扩展默认开启“上下文满时自动跳转新会话”和“新会话自动注入提示词”：

- 检测到上限横幅（中英文都认，连续两次命中才判定）后，先抢救正在录的那一段，再切到新会话。
- 进入新会话后自动发一句提示词，让 ChatGPT 去回忆记忆里的任务要求。提示词内容可在面板里改，默认是：

  ```text
  回忆关于会议记录/翻译相关的任务要求，根据要求开始任务。
  ```

- 提示词是在**开录之前**发出去的：发完、并且 ChatGPT 开始回忆之后，才会点“听写”。新会话刚打开时停在空白页（地址还是 `/`），扩展也会先把提示词发掉再开录。
- 注入的这条消息不会被当成转录段落落盘。
- 切到新会话后，落盘会换一个新文件重新开始编号，不会接着写进旧文件。
- 属于旧会话、已经匹配不上的段落会标成“待处理”，面板里可以一键清空。

这两个开关都在面板的“提示词与自动化”区块里，不需要可以关掉。

## 激进程度怎么调

面板里的“偏置”滑块是**在你自己节奏基础上的相对调整**，不是直接填秒数：工具先按当前课程学到的自动基准定一条基线，滑块再在它上面加减（−3 最保守，+3 最激进）。

两端差得很远，按这个数量级理解：

| 位置 | 停顿门槛（没学到节奏时的兜底值） | 开始收紧的时机 | 一句话 |
| --- | --- | --- | --- |
| 最保守 | 约 9.6 秒停顿才发 | 说满 72 秒才开始收紧 | 一段能录好几分钟，几乎只在真停顿时切 |
| 默认 | 约 2.4 秒 | 说满 18 秒 | 多数讲师适用 |
| 最激进 | 约 0.9 秒 | 说满 6 秒 | 句子级别切，容易把话切碎 |

“说满 X 秒才开始收紧”的意思是：前面 X 秒里用最宽的门槛，之后门槛慢慢往下压，说得越久越容易收口。

觉得切得太碎就往左拉，觉得等太久就往右拉；一门课一个偏好，切换课程时会各自记住。

### 两段之间的空窗

一段发出去到下一次开始录音之间必然有一段空窗，因为 ChatGPT 在生成回答时“听写”按钮是灰的，这段时间抢不了。扩展的做法是盯着按钮，它一变可点就立刻开录，实测点击到真正进入录音约 0.5 秒。

回答越长空窗越长，这是 ChatGPT 那边决定的，不是扩展在等。

## 隐私与安全

- 只有打开“归档 GPT 回答”时，扩展才读取已发送的用户转录及其后的 GPT 回答。
- 保存内容先进入浏览器扩展的本地队列，再通过 `127.0.0.1` 交给本地 writer。
- writer 不会连接外部服务器。
- 生成的 Markdown、日志、浏览器配置和个人目录路径默认被 `.gitignore` 排除。
- 不要公开上传真实转录、账号 Cookie、浏览器配置或包含私人路径的日志。

安全问题请按 [`SECURITY.md`](SECURITY.md) 处理。

## 更新后重启 writer

Node.js 会在启动时读取 `writer.mjs`。如果你更新了项目但 writer 已经运行，旧进程仍会继续使用旧代码。

先关闭原来的 writer 窗口，再重新双击：

```text
writer\start-writer.bat
```

若端口 `8799` 已被现有 writer 占用，重复启动会显示“本服务可能已经在运行”，窗口会停住等待你阅读提示。

## 常见问题

### 面板显示 writer 离线

1. 双击 `writer\start-writer.bat`。
2. 打开 `http://127.0.0.1:8799/ping`，应看到 `ok: true`。
3. 如果仍有旧 writer 在后台运行，结束监听 `8799` 的 Node 进程后重新启动。

### 文件夹选择器没有出现

直接双击 `choose-save-folder.bat`，或在面板中点击“选择文件夹”。

### 找不到 ChatGPT 按钮

先刷新 ChatGPT，再在 `edge://extensions` 里点扩展的“重新加载”。内容脚本按扩展加载缓存，只刷新页面不会拿到新代码。

若页面刚改版：ChatGPT 现在的听写按钮链是「听写 →（录音中）停止听写 / 发送 → 正在完成听写」，旧的「转录并发送」已经不存在。需要更新 `extension/page-hook.js` 中 `BUTTON_LABELS` 的文案。

### 回答没有归档

查看面板中的保存状态：

- “待保存”：队列还在等待回答或 writer。
- “落盘失败”：任务已保留，修复目录、分类或文件权限后重试。
- 缺少分类：在“失败段落分类”中明确选择，扩展不会用当前分类猜测旧任务的去向。

长对话里 ChatGPT 会把早期的轮次从页面上移除，那些段落就再也匹配不上了。切换会话时扩展会把它们标成“待处理”，确认不需要后用面板的“清空失败记录”清掉，别让队首一直堵着。

### 文件落在了没想到的位置

面板底部会显示完整的实际目录和示例文件名，先看那里。常见两种情况：

- 根目录不是你以为的那个：面板“① 落盘根目录”重新选一次，`writer/config.json` 的 `rootDir` 会被一起改掉。
- 课程名和磁盘目录名对不上：加 `courseDirs` 映射（见上文“课程目录别名”）。

## 配置

配置示例：

```powershell
Copy-Item writer\config.example.json writer\config.json
```

首次选择目录时，writer 也会自动创建 `config.json`。不要把这个文件提交到仓库。

`subDir` 是分类目录下的子文件夹默认值，留空则文件直接写入课程目录，详见“本地归档格式”。

`courseDirs` 把课程名映射到磁盘目录名，一门课有两个叫法时也只用一个目录：

```json
"courseDirs": {
  "课程简称": "磁盘上的目录名"
}
```

键是面板里显示的课程名，值是磁盘上的目录名。没写映射的课程按原名建目录。改完重启 writer 生效。

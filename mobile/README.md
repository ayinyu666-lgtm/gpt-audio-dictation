# 手机听写助手

这是独立 Android 应用，控制手机前台 ChatGPT 中文界面。自动录音流程不采集音频、不读取视频、不连接电脑；可选的手动麦克风探针会短暂采样。保持手机解锁、亮屏，进入需要录音的普通对话并确认麦克风已经正常工作。可按用户原有方式播放视频供手机采音；采音质量和扬声器、麦克风的实际条件有关。

## 悬浮窗

服务启用后会出现一个小圆钮（`TYPE_ACCESSIBILITY_OVERLAY`，不需要额外“显示在其他应用上层”权限，服务关闭即消失）。

- **单击**：未运行时开始；运行中暂停。暂停只是停止助手的自动动作，**不会**点击或在 ChatGPT 里取消当前录音，当前录音留给你处理。
- **长按 0.75 秒**展开设置面板：每段最长秒数、停顿激进程度、噪音忽略、测试诊断。
- **拖动**：按住可移动位置，避免挡住 ChatGPT 的录音按钮。
- 悬浮窗上的触摸不会触发“检测到手动操作，已暂停”，也不会点到 ChatGPT 的任何控件。

## 噪音忽略

ChatGPT 的波形是**相对对比**，不是真实音量：安静时敲键盘也可能看起来是连续的明显波形。所以本应用不把“画面高”当成“有人在讲话”。

- **停顿激进程度**：安静多久之后发送。左边更保守，右边更灵敏。
- **噪音忽略**：多大的起伏才算“活动”。左边少忽略（更灵敏，更容易把键盘声当活动），右边多忽略（更保守，需要明显高于背景才算活动）。
- 两个参数互相独立：激进程度管“等多久”，噪音忽略管“什么算声音”。
- 默认值为“自动”，行为与旧版一致。调高噪音忽略后，持续的小噪音更不容易触发停顿发送，但**最长时长兜底始终有效**。

## 自适应的停顿与噪音

这两个参数会自动适应，不需要你每节课重调。

**语速（等多久）**
- 助手从每段录音里学习“说完一段到下一次开口”的实际间隔。前 3 个完整周期仍用默认 2.4 秒；**从第 4 个周期起就开始按你实际的节奏缩短或延长**，不需要攒满 12 次。
- 讲课快、停顿短（例如 0.8 秒就接下一句）时，等待会明显缩短，不会死等固定的 2.4 秒。
- 采样约 1 秒一次，比这更短的停顿只能看出“有停顿”而量不出精确长度。连续出现 3 次这种极短停顿，会判定为快语速并把等待压到约 1.4 秒；偶尔一次不会改变。
- 若之后出现明显较长的停顿，会清除“快语速”判断，重新跟随当前节奏。
- “停顿激进程度”仍是你在这之上的手动微调（左保守 / 右灵敏）。

**噪音（什么算声音）**
- 助手统计最近 24 帧里有多少帧“分不清是活动还是背景”。比例越高，说明画面越吵或越乱。
- 吵的时候自动收紧两头：判定“算作活动”的门槛提高，同时要求的停顿时间变长（最多延长到 1.55 倍）。安静下来后会自动回落。
- “噪音忽略”是叠加在这之上的手动档位：自动为 0，往右更保守，往左更灵敏。
- 这个自动判断依据的是**画面稳定性**，不是音量。它无法区分人声、键盘和空调，只能反映“画面是否持续难以分辨”。

**边界**
- 所有自适应都只影响“要不要按停顿发送”。最长时长兜底始终照常执行。
- 画面无效、截图失败、区域变化时仍按原规则放弃停顿判断，不会硬猜。
- 这些参数目前只有合成画面测试和离线验证，真实课堂的语速分布与底噪仍需实测校准。

## 会话命名（供电脑端归档）

开始一段新对话时，助手会自动发送一条命名消息：

```
本会话命名为：2026-10-31-23:00
```

格式固定：`本会话命名为：` + `YYYY-MM-DD-HH:mm`，可追加后缀（例如 `-课堂`）。电脑端匹配这个前缀并取前 16 个字符，就能把录音归档到对应时间。

触发条件很严格，四个条件同时满足才会发送：输入框显示空会话占位符（`回复 ChatGPT`）、录音入口可用、没有正在录音、本轮尚未命名过。任何一条不满足就跳过——漏命名只是少一个标签，误命名会污染已有课程。

**限制**：只做了逻辑模拟测试（格式、去重、12 段只命名一次），尚未在真机验证 ChatGPT 是否按预期暴露占位符和发送按钮。

## 使用

1. 安装 debug APK，在 Android 无障碍设置中启用“听写助手”，并允许通知以便看到状态及停止按钮。
2. 在助手里设定每段秒数（5–1800，初测建议 10–15），点“开始并打开 ChatGPT”。助手只在 ChatGPT 前台且识别到唯一的中文“语音输入”时尝试开录。
3. 识别到“取消录制”和“点击发送录音”后开始计时；到最长时间，或视觉停顿满足条件时，只点击一次“点击发送录音”，不点击“停止录制”。**每种触发都只点击一次。**
4. **入口一旦返回可用就立即开始下一段，不等 GPT 回答，也不做任何投递判断。** 助手不读取聊天消息，不判断有没有转写出来、发送成功还是失败——这些都是 ChatGPT 自己的事。它只做两件事：判断什么时候点发送，以及发送后一看到录音入口可用就立刻点录音。课上可以连续多段自动进行；内容请课后自己核对。
5. 因为不再逐段核验，请务必课后检查每段是否真的发出去了。助手不会提醒你哪段有问题——它没有能力知道。

停止自动操作不会提交或取消当前录音。可编辑输入框中有非空草稿时暂停并保留。仍保留的安全保护：出现多个同名控件、窗口切换、离开前台、锁屏、服务中断、手动触摸，或发送点击本身没成功时暂停，且**绝不重复点击发送**。除此之外没有别的暂停条件。

## 安装

从 GitHub Release 下载 `gpt-audio-dictation-android-0.9.4.apk`，在 Android 8.0（API 26）或以上安装。打开应用后：

1. 在 Android 无障碍设置中启用“听写助手”。
2. 允许通知，以便查看运行状态并随时停止。
3. 保持手机解锁、亮屏，打开 ChatGPT 中文界面。
4. 先短时间试录一段，确认界面、控件和录音质量正常后再正式使用。

APK 使用 Android 调试签名，适合直接安装和测试；应用商店发布需要你自己的签名密钥。不要从非本项目 Release 的来源安装同名 APK。

旧版本要求手动点“解除暂停”才能继续；新版已删除该按钮、该状态和对应提示。如果你还留着旧版 APK，建议直接换这个版本。

录音界面节点暂时缺失时，助手最多复查 3 秒；节点恢复后须在至少间隔 250 毫秒的观察中仍存在才继续，复查期间不会发送。持续不明就暂停。用通知观察实机试验；不要在试验期间运行 `uiautomator dump`，它可能重绑无障碍服务并中断流程。

只支持亮屏前台试验；锁屏、后台、保活、无缝采音均未验证。点击成功或入口返回都不等于转写准确。不同 ChatGPT 版本、语言、弹窗、节点结构、键盘及机型需要重新验证。此版不提供归档或可靠会话身份校验。窗口 ID 和工具栏相同也不代表同一会话；检测到窗口变化、前台丢失或手动触摸时暂停。

## 声波采样与确认边界

- 开始一段时，助手先判断“最长秒数”够不够让停顿检测真正生效：必须先积累约 8 帧建立可分辨参考，再等够你设定的停顿时长。秒数太短（例如 10 秒配默认倾向）时，通知会直接写“本段时长偏短，按最长时长发送”，不再假装检测到停顿。想用停顿分段就把最长秒数调大。
- 录音态确认后开始波形观察，每次最多一个请求，间隔约 1 秒。采样区由取消/停止按钮的实时范围推算；区域变化、识别异常、过期帧或截图失败不视为停顿。等待超过 2 秒丢弃本次请求，旧回调不会触发发送。Android 没有提供取消截图请求的接口：若系统一直不回调，为避免并发截图，会暂停后续截图，录音仍使用最长时长兜底；迟到回调释放资源后可恢复截图。最长时间到时，只要录音界面仍可确认，就按定时兜底发起提交；录音界面不明或安全条件不满足时暂停。截图或波形不可用时显示“停顿信号不可用，按最长时长发送”。最短录音 3 秒、连续视觉活动门槛 1.5 秒；波形不证明实际讲话，也不能区分讲话与背景噪音。
- 采样区域是实时量出来的，键盘弹出或界面重排都会让它移动。移动一次会丢弃已学参考、按新区域重新建立，停顿检测随后仍可恢复；同一段内反复移动（超过 3 次）说明这个位置学不出稳定参考，本段就只用最长时长兜底。**这条已从“永久失效”改为可恢复**：旧版一旦检测到区域变化就整轮不再检测。
- `AdaptivePausePolicy` 根据经过界面与新鲜度校验的视觉活动/安静变化积累停顿样本，并结合滑条七档倾向（−3 至 +3）调整所需停顿；新一轮开始重置，自动续录跨段保留，长时间信号无效或裁剪区域变化时清除学习。默认样本不足时使用初始规则。学习的是视觉变化而不是声源或语速，实际课堂效果、触发时延和噪音条件尚未完成实机验证。
- 无障碍服务已声明 `canTakeScreenshot`；截图 API 仅在 Android 11/API 30 及以上可用。当前 `WaveformCapture` 从系统截图的硬件位图先裁剪区域，再复制小块到软件内存；代码中会释放位图和 `HardwareBuffer`，不持久化图片。设备和系统内部的截图处理仍需实机验证。
- 旧版曾尝试用“右侧气泡是否新增一条”来推断发送结果，已在 0.2.0 移除。真机测量显示该方法不可靠：录音期间 ChatGPT 窗口常常不存在可滚动的会话容器（一次实测 53 个快照全部为 0），带文本的 `TextView` 只有 1–2 个，基线经常为空；而且右侧几何并不能证明这条消息属于本次提交，也不能区分助手消息、按钮或历史消息。用这种证据去“确认”只会造成虚假安全感，所以整条气泡确认链路已被删除。

## 测试诊断（仅 debug 版）

诊断默认关闭。安装本版后，在助手界面勾选“测试诊断”，再点“开始并打开 ChatGPT”；开关在下一次开始时生效。测试中观察通知，不要运行 `uiautomator dump`。自动流程暂停后，助手页面显示文件名和记录状态；取消勾选后，下一次开始不再记录。文件保留在应用私有目录，卸载应用会删除该目录。

每次开始生成一个 `files/diagnostics/diag-<随机标识>.jsonl`，上限 8 MiB。仅记录运行期间 **ChatGPT 前台活动窗口**的节点快照（包含消息、输入框和控件，并非只有消息），约每秒一次、发送动作前另强制一次；单次最多 1200 节点，`truncated` 表示可能不完整。还记录该包的无障碍事件类型、变化类型、窗口 ID、相对时间和状态；每秒最多保存 10 个事件，丢弃数量在下一次快照记录。停止、锁屏、离开前台或出错后不再采样。日志上限或写入失败只停止诊断，录音的保守逻辑仍独立运行。

每个节点记录树内编号、父节点、子序号、标准类名（非白名单为 `other`）、屏幕 bounds、可见/可点击/可编辑/可滚动等属性，以及少量固定控件的符号线索。文本、content-desc 和资源 ID 只记录 HMAC-SHA256 哈希，不写入原文或事件正文；密钥每轮随机生成、仅保存在运行内存中。因此**只能在同一日志内比较哈希**，不同轮次的哈希不可直接比较。日志仍含屏幕布局、时间和行为元数据，应按敏感数据保管；诊断日志不包含截图或录音，不上传。日志过大或超出节点上限会丢失证据，不应据此断言节点不存在。

测试结束后，可用 ADB 只读导出（把 ADB 路径、设备序列号和文件名替换为你自己的实际值）：

```powershell
$adb = '<Android SDK 路径>\platform-tools\adb.exe'
& $adb devices -l
$serial = '设备序列号'
& $adb -s $serial shell run-as org.gptdictation.assistant ls files/diagnostics
$logFile = 'diag-实际文件名.jsonl'
& $adb -s $serial exec-out run-as org.gptdictation.assistant cat "files/diagnostics/$logFile" > diag.jsonl
```

本 debug 包允许 `run-as` 读取自己的私有文件；这些命令不调用 uiautomator。`send_action_result` 只是无障碍点击 API 的返回值，不证明转写或投递成功。诊断本身还未在手机上验证，开启后可能增加采样开销；建议先用短测试，检查 `before_send`、后续快照、`truncated` 与上限状态。当前没有自动消息确认；连续多段仍待真机验收。

## 构建

为本机工具目录设置当前 PowerShell 进程的环境变量（替换成你自己的 Java、Android SDK 与 Gradle 路径）：

```powershell
$env:JAVA_HOME = '<JDK 17 路径>'
$env:ANDROID_HOME = '<Android SDK 路径>'
$env:ANDROID_USER_HOME = '<Android 用户缓存路径>'
$env:GRADLE_USER_HOME = '<Gradle 缓存路径>'
$env:PATH = "$env:JAVA_HOME\bin;$env:PATH"
& '<Gradle 8.9 路径>\bin\gradle.bat' --no-daemon --console=plain :app:assembleDebug
```

运行位置是 `mobile`。产物为 `app/build/outputs/apk/debug/app-debug.apk`，需 Android 8.0（API 26）或以上。首次构建可能需要联网下载 AGP 和 SDK 依赖。波形截图 `takeScreenshot` 需要 Android 11（API 30）或以上；更低版本自动退回最长时长兜底。

## 麦克风探针（可选，默认不启用）

助手界面有“测一次麦克风”按钮，是**手动触发、测完立即释放**的探针。它会返回三种结果之一：本助手收到非静音数据 / 收到的是静音流 / 麦克风暂不可用。

限制必须说清楚：

- **只反映本应用自己拿到的音频**，不证明 ChatGPT 同时在正常录音。安卓音频并发由系统决定，通常最后开始录音的应用优先，后台或第二个录音者常常被静音，也可能拿到静音流。
- 所以“收到非静音数据”**推不出**“GPT 也听到了”。真机是否互相影响必须实测。
- 不保存、不上传、不转写音频，读一小段即释放并调用 `stop()`/`release()`。
- 录音流程**从不**自动开麦；不点这个按钮就不占麦克风。默认仍走截图波形路径，随时可以不管它。
- 安装包申请了 `RECORD_AUDIO`，仅供这个手动按钮使用；不给权限也不影响波形方式。

## 离线测试

纯 Java 决策逻辑（波形判定、自适应停顿、裁剪追踪、采样策略、哈希脱敏）不依赖 Android API，可以用 JDK 直接在主机上跑，不需要手机或模拟器。测试源码在 `app/src/hostTest/java`（**不在** `src/test`，避免被 Android 单元测试编译链捡走）：

```bash
cd mobile
bash run-host-tests.sh
```

脚本会把上述纯类连同测试类一起 `javac` 编译到 `build/host-test-classes`，逐个运行。合成波形和纯逻辑测试不需要手机；依赖个人采集样本的测试只在提供对应本地样本时运行，公开包不包含这些样本。

## 已知限制

- ChatGPT 的手机界面、语言、弹窗和控件会变化；不同机型、系统版本和 ChatGPT 版本需要重新验证。
- 工具依赖无障碍点击和屏幕截图推导的波形，不读取 ChatGPT 的聊天内容，也不保证每段转写或发送成功。
- 请先使用可丢弃的测试会话；不要在没有人工复核的情况下把自动结果当作完整课堂记录。
- 麦克风探针只测本应用是否收到声音；与 ChatGPT 同时录音可能互相影响。

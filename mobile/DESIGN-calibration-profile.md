# 设计 v2：环境学习库（底噪 / 说话电平 / 停顿 / BGM）

状态：**当前实现的说明与迭代依据**
原则（按你的要求）：**本轮只负责采数据，下一次发送时用上一轮（最近几轮均值）的参数**。不追求本轮立刻最优。

---

## 1. 为什么要"跨轮学习"而不是"本轮自适应"

判定要现场估：安静电平、说话电平、停顿长度。现场估需要样本，样本靠截图，于是：

- 冷启动预热 8 帧；
- 中途界面变化、档位调整、切段都可能触发重建；
- 一段 15 秒，预热就吃掉大半，剩下不够走完"确认说话 → 确认回落"。

**结论**：不是参数没调好，而是每一轮都从零开始。正确做法是把每一轮的结论存下来，下一轮直接当作初值。

---

## 2. 四类参数统一走"采集 → 存库 → 下轮先用"

| 参数 | 本轮怎么采 | 下轮怎么用 |
| --- | --- | --- |
| **安静电平** quietLevel | 判定为 quiet 的帧的活动度分布 | 直接作为 `floor` 初值，跳过预热 |
| **说话电平** speechLevel | 判定为 active 的帧的活动度分布 | 直接给出 `activeLimit` 的起点 |
| **停顿长度** pauseMs | 每次"视觉停顿触发发送"时，从最后一次 active 到发送的实际间隔 | 作为停顿需求的初值（替代固定默认值） |
| **环境分类** env | 运行前 3 秒的帧特征 | 决定用哪一套判定规则（见 §3） |

### 2.1 轮次聚合，而不是逐帧滑窗

每次运行结束时产出一条 **RunSummary**：

```
RunSummary { env, quietP10/P50/P90, speechP50, pauseMsP50, frames, endedAt }
```

库里对每个环境保存**最近 K=5 条** RunSummary。下一轮开始时：

```
先验 quietLevel   = 最近 K 条的加权中位数（越新权重 1.0 / 0.8 / 0.6 / 0.4 / 0.2）
先验 speechLevel  = 同上
先验 pauseMs      = 同上
```

这样：
- 一次异常（比如某轮刚好在走廊）不会毁掉库；
- 环境缓慢变化会自然被最近的几轮带走；
- **符合"本轮采集、下轮使用"**：第一轮慢，第二轮起就快。

### 2.2 采集失败也要留痕迹

若某轮中途停止（用户手动停、服务被系统杀），只要采到 ≥20 帧就写一条 `partial` 摘要，标记为低权重（0.3），下次聚合时参与但不主导。

## 3. 环境分类：三档常规 + BGM 三档音量

### 3.1 分类

| 类 | 名称 | 特征（前 3 秒） |
| --- | --- | --- |
| E0 | 安静 | 电平低（<0.18），波动小，quiet 帧占绝大多数 |
| E1 | 一般 | 电平中等（0.18–0.35），有起伏 |
| E2 | 嘈杂人声 | 电平高（≥0.35），起伏大（人声叠加） |
| **M1** | **BGM-轻** | 电平 0.22–0.35，**几乎无静默帧**（quiet < 15%），波动中等且周期性强 |
| **M2** | **BGM-中** | 电平 0.35–0.50，同上持续性 |
| **M3** | **BGM-重** | 电平 ≥0.50，同上持续性 |

判定顺序：**先判"有没有持续声底"**（quiet 帧比例 < 15% 且电平长期不落），有则进 M 类，再看电平细分；否则按 E0/E1/E2 分。

### 3.2 BGM 为什么不等于前三种

前三类的判定是"绝对电平高低"；BGM 下**整体电平被音乐抬高**，音乐不停就不会出现"安静"画面，绝对阈值必然失效。

BGM 类的判定必须改成 **增量 + 调制**：

- **增量**：`delta = 当前活动度 − BGM 稳态电平`。说话时波形在音乐之上再抬一段，回落后 delta 接近 0。
- **调制**：说话带来的是**不规则快速起伏**；纯音乐是**规律周期起伏**。用短窗内"相邻帧差分的方差 / 均值"区分。
- **停顿**：`delta` 连续 N 帧低于阈值。因为音乐不会停，不能用"画面静止"。

**BGM 稳态电平必须来自库**：冷启动时无法可靠区分"音乐"和"一直在说话"，所以 BGM 类在**没有可信先验时只用最长时长兜底发送**，第一轮采集完成后第二轮才启用视觉停顿。这正是"第一轮学、第二轮用"的最佳用例。

## 4. 判定流程改动

```java
// 现在
if (recentCount < 8) return INVALID;              // 8 帧预热

// 改为
if (!hasPrior && recentCount < 8) return INVALID; // 有先验就不预热
```

有先验时用先验合成 8 个"虚拟样本"填进 recent 窗口（可被真实帧快速覆盖），第 1 帧就能给出 voiced/quiet。

按环境切换判定规则：

```
E0/E1/E2 → voiced = activity >= activeLimit(先验+在线)
M1/M2/M3 → delta  = activity - bgmBaseline(先验)
           voiced = delta >= deltaLimit && modulation >= modulationLimit
           quiet  = delta <  deltaLimit 连续 pauseNeed 帧
```

## 5. 设置页结构性优化

现在是一整列卡片、学习能力完全没有入口。重构成四组：

```
┌ 运行状态 ──────────────────────────────┐
│ 服务已启用 · 当前环境：安静（自动）        │
│ 最近事件：第 3 段录音中…                  │
│ [开始并打开 ChatGPT]  [停止助手]          │
└───────────────────────────────────────┘
┌ 环境学习 ──────────────────────────────┐
│ 当前环境：安静（自动识别）  [手动切换 ▾]   │
│ [ 学习当前环境 ]   ← 采样 5 秒后写入库     │
│ 已学习：安静 3 次 · BGM-中 1 次  [查看][清空]│
│ 停顿倾向 ▬▬▬●▬▬  噪音忽略 ▬▬●▬▬▬        │
└───────────────────────────────────────┘
┌ 录音 ─────────────────────────────────┐
│ 每段最长秒数  [15 秒 ▾ / 拖动]           │
│ 采样节奏：( ) 省电  (●) 灵敏              │
└───────────────────────────────────────┘
┌ 诊断（可折叠） ────────────────────────┐
│ 调试日志 [开/关]   导出诊断                │
│ 打开无障碍设置                            │
└───────────────────────────────────────┘
```

要点：
- **「学习当前环境」是一等入口**：点击后后台采 5 秒，把当前环境的 quiet/speech/pause 统计写进库，并弹出结果（识别为：BGM-中，稳态电平 0.42，样本 40 帧）。
- **当前环境可视化**：让用户知道系统认为现在是哪种环境，可手动覆盖。
- **库可见可清空**：避免"学歪了没救"。
- 诊断收进折叠区，不再占据主界面。

## 6. 安全边界（防误发）

1. **先验只影响判定速度，不降低发送门槛**：`SEND_PAUSE` 仍要求本轮真实出现过连续说话（qualifiedActivity）。
2. **BGM 类无可信先验 → 不启用视觉停顿**，只走最长时长兜底。
3. 库损坏保护：`quietP50 >= speechP50`、样本数 < 5 → 丢弃该环境条目。
4. 陈旧降权：>30 天权重 ×0.5，>90 天丢弃。
5. 环境切换保护：连续 3 帧分类一致才切换环境，避免门口走两步换库。

## 9. 取舍与遗留

- **第一轮仍然慢**：没有库就没有先验，只能等第一轮采完。可接受。
- **BGM 首次不可用视觉停顿**：同上，第一轮靠最长时长兜底。
- **六类是否够**：可能遇到"音乐 + 有人说话"混合场景，先按 M2 处理，看实测再定。
- **库存在本机**：换手机/重装会丢，属于可接受损失。
